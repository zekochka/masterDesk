# MasterDesk — AI функциясының карточкасы (ЛЗ-12)

**Күні:** 17.11.2026  
**Жоба:** MasterDesk, TechPoint сервис орталығының жөндеу өтінімдерін басқару веб-жүйесі  
**Команда:** Амир — PM / Angular; Ханкелді — .NET / PostgreSQL  
**Күйі:** офлайн пилот. TechPoint тарапынан өндірістік пайдалануға рұқсат берілген жоқ.

## 1. Іскерлік мәселе

Менеджер клиенттің еркін мәтінін оқып, өтінім өрістерін қолмен толтырады. Бір сөздің әртүрлі жазылуы, қысқартулар және қазақша-орысша аралас сөйлемдер санатты таңдауды қиындатады. Мұндағы мақсат — менеджерге **форма үшін бастапқы ұсыныс** беру; құрылғыны диагностикалау емес.

## 2. Ұсынылатын функция

**Ақылды өтінім құрастыру (AI-assisted form prefill).** Менеджер клиент хабарламасын енгізеді. Қызмет үш өрісті ұсынады:

- `device_model` — құрылғының нақты моделі немесе `UNKNOWN`;
- `category` — шағым санаты: `DISPLAY`, `CHARGING`, `BATTERY`, `POWER`, `OVERHEATING`, `AUDIO`, `SOFTWARE`, `OTHER`;
- `incident` — нақты айтылған оқиға: `DROP`, `LIQUID`, `NONE`.

**Мысал:** «Айфон 13 про құлап қалды, экраны көрсетпейді» → `iPhone 13 Pro / DISPLAY / DROP`. Бұл **алдын ала ұсыныс**, нақты жөндеу диагнозы емес.

## 3. Шекаралар

**Жасайды:** мәтіннен өріс мәндерін ұсынады; операторға түзетуге мүмкіндік береді; бастапқы мәтінді сақтауға мүмкіндік береді.

**Жасамайды:** жөндеу құнын есептемейді; құрылғының нақты ақауын медициналық/техникалық сарапшы тәрізді растамайды; тапсырысты автоматты түрде сақтамайды; шеберді автоматты түрде тағайындамайды; кепілдік бойынша шешім қабылдамайды.

## 4. Өлшемдер

| Түрі | Метрика | Ұсынылатын пилот критерийі |
|---|---|---|
| Бизнес | Менеджердің 1 өтінімді толтыру уақыты, секунд | Кейінгі A/B сынақта қолмен толтырудан кемі 25% жылдам |
| Бизнес | Оператордың AI ұсынысын түзету үлесі | Бақылау және динамика (әзірге өлшенбеген) |
| Модель | Category Accuracy | ≥ 85% |
| Модель | Category Macro F1 | ≥ 0.85 және baseline-нан ≥ 0.05 жоғары |
| Модель | Device exact match | ≥ 95% |
| Модель | Incident exact match | ≥ 95% |
| Қауіпсіздік | Автоматты түрде сақтау | 0 жағдай; міндетті адам растауы |

Бұл — **алдын ала белгіленген мақсаттар**, орындалған факт емес. Екі промпт та осы өлшемдер бойынша бағаланады. Белгілі бір санатта модель едәуір нашар болса, жалпы орташа баллға қарап енгізбеу керек.

## 5. Баламалар

1. **Baseline:** 28 реттелген кілтсөз ережесі, 22 құрылғы моделін ажырататын regex үлгісі. Орындау шығыны өте аз; еркін тілге икемі әлсіз.
2. **Qwen2.5:3b + Ollama:** дайын ашық LLM, zero-shot және few-shot промпттар. Модельді қайта оқыту талап етілмейді. Бастапқыда локал офлайн сынақ.
3. **Коммерциялық API:** сапа жеткілікті болса ықтимал өнімдік нұсқа; жеке деректерді жіберу мәселесі алдын ала шешілуі тиіс. Құнын салыстыру үшін GPT-6 Luna бағасы алынды, ол **тестіленген Qwen емес**.

## 6. Деректер және бағалау

- `evals/dataset.jsonl`: **40 синтетикалық сценарий**, 8 санат × 5 мысал, түрлі құрылғылар мен қазақша/орысша сөйлемдер.
- Әр жазбада `id`, `text`, `expected.device_model`, `expected.category`, `expected.incident` бар.
- `D04`, `D05`, `C05`, `B01`, `B03`, `H04`, `A01`, `S01`, `S03` мысалдары қысқа/аралас/бейресми мәтін салдарынан қиын.
- Қазір dataset TechPoint-тың нақты өтінімдері **емес**. Эталондар материал дайындау кезінде алдын ала қойылған; Амир мен Ханкелді тәуелсіз қарап, келіспеген тұстарды шешкенін тек нақты орындаған соң ғана тіркеу керек.
- Модельге осы 40 эталон жауабы **берілмейді**. Few-shot мысалдары басқа, жеке жазылған.

## 7. Орындалған және орындалмаған жұмыс

| Құрамдас | Күйі |

## 8. Техникалық ықтимал интеграция (осы ЛЗ-да міндетті емес)

`Angular өтінім формасы → POST /api/ai/parse-order (.NET) → локал Qwen / сенімді API → JSON ұсыныс → адам тексеруі → тапсырысты сақтау`.

Құпиялылық: нақты клиент аты/телефоны/мекенжайы, құрылғы сериялық нөмірі және жеке контент **сыртқы AI провайдеріне жіберілмейді**, ал бастапқы сынақ тек синтетикалық мәтіндермен жүргізіледі.
