# MasterDesk командасының жұмыс тәртібі

**Команда:** Амир — Project Manager / Frontend Developer (Angular); Ханкелді — Backend Developer (ASP.NET Core, PostgreSQL).  
**Тапсырыс беруші:** TechPoint, өкілі — Байкенов Оспан.  
**Мәртебе:** команда қолдануына ұсынылған ережелер.

## Тапсырмалар ағыны

1. **Backlog** — алдағы жұмыс; әлі алуға дайын емес.
2. **Ready** — сипаттамасы, қабылдау критерийі және иесі анықталған.
3. **In progress** — орындаушы нақты жұмыс істеп жатыр.
4. **Review** — нәтиже екінші қатысушының тексеруінде.
5. **Blocked** — нақты кедергі бар; оның себебі Issue ішінде жазылады.
6. **Done** — талаптары орындалған және тексерілген жұмыс.

**Ескерту:** жаңа Issue әдетте Backlog-та болады, Review-ға автоматты түрде қойылмайды. WIP мүмкіндігінше бір адамға бір белсенді тапсырмадан басталады; кейін шынайы жүктемеге қарай реттеледі.

## Карточкадағы өрістер

- **Size:** S (шағын), M (орта), L (ірі; жұмысқа алар алдында бөлу қажет).
- **Owner:** Амир немесе Ханкелді — тапсырма үшін жауапты адам; бұл GitHub Assignee-ден бөлек мәтіндік өріс болуы мүмкін.
- **Iteration:** жоспарланған жұмыс аптасы (Github-та арнайы Iteration өрісі).
- **Risk ID:** байланысты тәуекелдің коды немесе `—`, егер байланыс әлі жоқ болса.

## Git тәртібі

- Негізгі тармақ: `main`.
- Бір міндет — бір branch: `feat/MD-12-order-status` немесе `docs/MD-08-adr`.
- Бір тармақты мүмкіндігінше **3 күннен** ұзақ ашық қалдырмау.
- Коммит: `feat:`, `fix:`, `docs:`, `test:`.
- Өзгерістер Pull Request арқылы біріктіріледі; екінші адам тексереді.
- Әзірге автоматтандырылған CI жоқ болса, оны жұмыс істеп тұр деп көрсетпеу.

## Апталық ритм

- Апта басы: 15–20 минут жоспарлау; Ready тапсырмаларын және тәуелділіктерді таңдау.
- Апта ортасы: кедергі болса, Blocked себебін Issue-де жазу.
- Апта соңы: дайын нәтижені тексеру, келесі аптаға басымдықтарды өзгерту.

## Қауіпсіздік

Парольдер, токендер және TechPoint клиенттерінің жеке деректері репозиторийге салынбайды. Жобалық талқылауда құпия деректердің орнына тестілік мысалдар қолданылады.
